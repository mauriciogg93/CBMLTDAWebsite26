# DEVELOPMENT.md — developer reference for this repo

> Read this only in **development mode** (see [AGENTS.md](AGENTS.md) §2): the person writing
> is the developer. In operation mode (the owner) nothing here applies beyond what AGENTS.md
> already says. Language rule: site copy is Spanish; docs, comments, config and commit
> messages are English.


## 1. What this project is

The website of CBM Ltda (cbmltda.com.co): sales of banking equipment (bill/coin counters,
detectors) and packaging equipment (strapping tools, strap, staplers) with technical
service, in Medellín since 1983. Migrated from WordPress to **Astro + Tailwind 4, 100 %
static** (no SSR, no database, no backend). Goal: generate WhatsApp leads and be trivial for
its owner to maintain with an assistant (AGENTS.md §1).

## 2. Stack and invariants (do not change without the developer's explicit agreement)

- Astro `output: 'static'` + `trailingSlash: 'always'` + `build.format: 'directory'` — this
  combo behaves the same on Cloudflare Workers and on Apache hosting; never change one
  without the others.
- Tailwind CSS 4 via `@tailwindcss/vite`; color tokens in the `@theme` of
  `src/styles/global.css` (CBM blue `--color-marca-600`, accent `--color-acento-600`, CTA
  green `--color-whatsapp-oscuro`).
- **No UI framework and no client-side JS**, except the mobile menu (script in
  `Header.astro`). No CDNs, no analytics. Fonts: system stack; if web fonts are authorized
  they go through Astro's Fonts API (`fonts` in `astro.config.mjs`, `local` provider over
  the woff2 files of `@fontsource-variable/*`, `<Font preload />` in the layout), never by
  importing fontsource's CSS.
- Icons with **astro-icon + Iconify** (`lucide` for UI, `simple-icons` for brands): inline
  SVG resolved at build time, zero runtime JS. No hand-drawn SVG and no PNG icons; custom
  icons would go in `src/icons/` (folder that does not exist today).
- `src/site.config.ts` is the single source of business/contact data. No phone numbers or
  emails hard-coded in components or pages.
- Secrets never enter the repo (`.env` is gitignored). The CI deploy uses none.
- Language: site copy (data files, page text, labels, alt text) in Spanish; docs, comments,
  config, scripts and commit messages in English. Identifiers stay as they are.

## 4. Procedures

- **New machine** (the developer's or the owner's, any OS): clone, `npm install`, then
  `npm run doctor` green. It checks Node against `.node-version` and the `brand` minimum,
  npm, git, headless Chrome, `agy` / `claude`, the launchers, `node_modules` and `sharp`, the
  `@emnapi` lockfile entries, `CLAUDE.md` as a symlink, git identity, origin, branch and
  clean tree, no rebase or merge left in progress, network, read and write access to origin
  (`git push --dry-run`, nothing is pushed), how far `main` is from `origin/main` (a `git
  fetch`) and port 4321. `FAIL` blocks publishing; `warn` is something to look at. Then
  `npm run build`.
- **New product**: photos to `src/assets/products/` → ONE new object in
  `src/data/products.ts` (the first image of the array is the cover; `corto` ≤ 160
  characters because it is the page's meta description). Nothing else.
- **New page**: create it in `src/pages/` with `BaseLayout` (+ `Seccion` for the body);
  `descripcion` ≤ 160 characters; add it to `nav` in `site.config.ts` only if asked.
- **Domain change**: `url` in `site.config.ts` + the `routes` block of `wrangler.jsonc`
  (hostnames only, `custom_domain: true`, the zone must already exist in Cloudflare and the
  hostnames must have no `A`/`CNAME` records left: API error 100117 otherwise) + push.
  Cloudflare creates the DNS records and the certificate. Then the zone settings of the
  PLAN.md runbook.
- **Tagline, colors or hero photo change**: `npm run brand` and commit `public/og.jpg` and
  `public/apple-touch-icon.png`.
- **Closing an iteration**: `npm run check` and `npm run build` green — the `postbuild`
  (`scripts/check-links.mjs`) already checks links, anchors, `<title>` and metas; its
  glued-text *warnings* get fixed too, never ignored. Visual QA with
  `npm run shots -- <dir> home=1440x900@<url>/ home-m=390x844m@<url>/ menu=390x844m@<url>/|click:#boton-menu`
  before showing the developer. Update PLAN.md (checklist + iteration log), small commits
  with English messages.
- **After a deploy**: `npm run verify` (or `npm run verify -- <url>`); CI does not run it.
  Zero failures and zero warnings is the target.
- **Updating dependencies**: `npm install <package>@latest` on macOS drops the `@emnapi/*`
  entries that `npm ci` requires on Linux (Workers Builds) from the lockfile: after
  updating, regenerate the lockfile from scratch (`rm -rf node_modules package-lock.json &&
  npm install`) and validate with `npm ci`. TypeScript 7 does not work: `astro check`
  (@astrojs/check 0.9) requires TypeScript 5/6; keep `typescript` on 6.x until
  @astrojs/check supports it.

## 5. Lessons that already cost time

- **Astro collapses whitespace next to inline elements**: `escríbanos a` + newline + `<a>`
  renders as "escríbanos acontacto@…". Keep the link and the text on the same line or put an
  explicit `{' '}` on both sides. The postbuild warns about the right side; the left side
  has to be eyeballed.
- **Tailwind 4 and `class:list`**: never pass through a component's `class` prop a utility
  the component already sets (`hidden` vs `inline-flex`, a text color): same specificity,
  CSS order wins and the override is silently lost. Wrap the component or add a real
  variant.
- **Dev server port**: if 4321 is taken, Astro moves to 4322/4323 without failing. Read the
  port from the output before curling or taking screenshots. `astro dev` and `astro
  preview` accept `--background` and are managed with `status|logs|stop`.
- **`<Image sizes>` describes the real column**: a generic `sizes` makes 2x screens download
  the next size up. Photos with `w-auto` + `max-h` reserve no space before loading (CLS):
  give them an `aspect-*` container or a fixed height.
- **Unbreakable words (URLs) overflow the grid**: `wrap-anywhere`, not `break-words`; only
  the former reduces the column's min-content.
- **Per-product og:image**: JPG at 1200 px; PNGs with transparency go to palette PNG at
  800 px (JPG would paint the transparent areas black). Astro never upscales: declare the
  real dimensions.
- **Cloudflare injects `<script>` into every HTML** when the zone has *JavaScript
  Detections* (Bot Fight Mode) or *Web Analytics* on: it lowers Lighthouse Best Practices
  and contradicts "no trackers". `npm run verify` compares the script count with `dist/`.
- **Custom Domains refuse hostnames that already have DNS records** (API error 100117,
  "already has externally managed DNS records"): wrangler's non-interactive override does
  not apply. Delete the `A` of the apex and the `CNAME` of `www` in the zone right before
  the deploy that enables `routes`; MX and TXT stay. Also, a `routes` block switches
  `workers.dev` off unless `workers_dev: true` is declared: the first domain deploy
  (2026-09-02) left the site with no public URL at all until the records were cleaned.
- **Lighthouse from the terminal**, mobile, against the published URL:
  `npx lighthouse <url> --output=json --output-path=./lh.json --chrome-flags="--headless=new"`
  then read `categories.*.score` and every audit with `score < 1`.

## 6. Working mode with the developer

- "Create a PR" never means push to `main`: branch from the local commits
  (`git switch -c <topic>`), push the branch, PR against `main` (`gh pr create` if
  authenticated; otherwise give the compare URL) and say in the PR that merging publishes.
  The local `main` stays ahead until the developer resets it after the merge; say so, do
  not reset it yourself.
- When the developer asks for a review ("what could be improved"), the deliverable is the
  findings, grouped technical / content, each with its evidence. If they then say "do
  everything you can": apply what needs no answer, verify (build, screenshots, `wrangler
  dev`), small commits per topic, and end with ONE numbered list of the questions only they
  can answer, each with a recommended option.
- Ask before adding dependencies or installing tools on the machine.
- Small commits with English messages, one topic per commit.

## 7. Windows notes

The owner's machine may be Windows: install Git for Windows, the Node 24 installer and
Google Chrome; `asistente.cmd` is the launcher (batch file, CRLF, prompt without accents so
the console code page cannot garble it). `git`, `npm` and `node` work from cmd/PowerShell;
`npm run verify` needs bash and curl, so run it from Git Bash. `npm run shots` / `npm run
brand` look for Chrome in `C:\Program Files\Google\Chrome\Application\chrome.exe`; set the
`CHROME` environment variable if it lives elsewhere. Push permission: the simplest is the owner
as a collaborator using HTTPS with the Git Credential Manager bundled with Git for Windows
(a browser sign-in on the first push). The operation-mode commands in AGENTS.md are written
one at a time because Windows PowerShell 5 rejects `&&`. `npm run doctor` checks all of this.
One more Windows trap: `CLAUDE.md` is a git symlink; with `core.symlinks` off (the default
unless Git was installed with symlink support and Developer Mode is on) it is checked out as
a text file containing `AGENTS.md`, and Claude Code loads no rules. `agy` is unaffected
because the launcher makes it read AGENTS.md. The doctor reports it, with the fix.

## 8. Publishing rule

**A push to `main` publishes the site**: Cloudflare Workers Builds (connected to the repo,
runbook R1 in PLAN.md) installs the dependencies, runs `npm run check && npm run build` and
deploys; a red build does not deploy. Branches other than `main` produce *versions* with no
traffic, not deploys.

- In **operation mode** (AGENTS.md §1) publishing is part of every request: always commit + push.
- In **development mode** local commits are free, but NEVER push `main`, deploy or publish
  unless the developer explicitly asks for it in the conversation.

**Several computers commit to the same `main`** (the owner's machine in operation mode, the
developer's machines, parallel sessions in one working copy). The protocol that keeps that
conflict-free is in AGENTS.md §1.2 (steps 0 and 3) and applies in development mode too:

- **Sync at the start of every task**, not only when a push is rejected: with a clean tree
  and nothing unpushed, `git pull --rebase origin main` is a fast-forward and cannot
  conflict. The conflict window shrinks from "days since the last session" to the minutes
  the task takes. Leftover uncommitted changes are committed first, never stashed.
- **Commit first, rebase after.** `git stash` + pull + `stash pop` is not a transaction:
  the pop can conflict too and leaves markers in the tree with the stash still around
  (`git pull --rebase --autostash` has the same hole). A local commit followed by `git pull
  --rebase` is the atomic version: a conflicting rebase is undone whole with `git rebase
  --abort`, the commit survives, the tree is clean.
- **On a conflict, nobody edits markers.** Abort, keep the commits on a `pendiente/…`
  branch, `git reset --hard origin/main`, redo the change on the fresh files, verify, push.
  The assistant has the request in context, so redoing it is cheaper and safer than
  resolving hunks. After any rebase that brought commits, `check` + `build` run again
  before the push, and commits you did not author are named to the developer.
- **PLAN.md is the hot file** (every session appends to it): `.gitattributes` gives it
  `merge=union`, so git keeps both sides instead of stopping. If both sides edit the same
  line, both versions stay; tidy it when you see it.
- `npm run doctor` reports a rebase left in progress and how far `main` is from
  `origin/main` (ahead, behind, diverged) with the command to run.
